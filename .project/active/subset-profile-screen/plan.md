## The Point

A modeler needs one command, `check`, that says before anything is written whether `generate` will build their model, every reason it won't, and every finding the shared subset screen has, marked "not assessed" wherever the screen could not decide. `generate` must print the same findings in the same form. [ORCHESTRATOR]

That answer is only worth having if it is the generator's own answer. The generator's route alone decides refused or builds; the screen only reports, and no route gains a refusal keyed on the screen, its version or its failure. [OWNER-ratified 2026-10-20, `briefs/align.md` Q1] Changing what the generator accepts or refuses (RG-1), String policy (RG-2), and merges and ADR filing (RG-3) stay with the owner. [OWNER, epic gates 2026-10-18] The product never makes a bad model generate. [`.project/product/0003`, owner-verbatim]

So the work has three obligations: `check` must be the generator's route minus the writes, not a copy of it; the screen must be unable to change the generator's answer; and a refused `generate` must leave the destination as it found it, which today fails for `PARAM_FIELD_COLLISION`.

Engineering bar for this plan [ORCHESTRATOR]: a clean refactor, each phase leaving the suite green, with behaviour-preserving moves in their own phases so each can be reviewed alone.

## Implementation Strategy

**The simple version.** First record exactly what the code does today (Phase 0). Then reshape the code without changing what it does, proving after each step that every generated byte and every refusal record is unchanged (Phases 1–3). Then make the behaviour changes one at a time (Phases 4–5). Then build the new parts, the screen and the report, beside the generator (Phases 6–7), and wire them into `generate` and a new `check` command (Phase 8). Phase 9 runs the spec's criteria over the whole corpus. Phase 10, the readiness rule, waits for the owner.

**Critical path.** 0 → 1 → 2 → 3 → 4 → 5 must run in order, because each pure move is proven against the state the previous one left. Phases 6 and 7 depend only on Phase 1 (the shared load) and can be built in parallel with 4–5. Phase 8 needs 3–7. Phase 10 needs the owner and Phase 8.

**First proof point.** Phase 0's reachability probe (the design's "de-risk first" item): a call closure from today's writers, joined with the site account, must show exactly the covered sites the design predicts (site 337, the nine `_preflight_constraint_names` calls, and site 338 through three renderer guards). The second is Phase 1's B1 test: the screen, run on the model the generator just elaborated, must equal 2a's stored screen answers on every 2a case. If either comes back different, stop and surface it (capture-fidelity law 4); later phases rest on both.

**Readiness rule independence.** D8 is PARKED with the owner. Phases 0–9 never assert READY or exit 0 on a real model. Phase 7 ships an interim `readiness()` that decides every case the owner's question does not touch and withholds READY on the rest (Phase 7, assumption A1). Phase 10 replaces only that function, its tests and the readiness line.
