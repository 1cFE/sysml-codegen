## The five difference mechanisms, each named once

1. **Provenance comments.** The live route records absolute checkout paths, the v6 route the
   portable `root-N/<relpath>` referent. Reaches generated bytes only as `SysML Source:` lines.
   The residual Slice 3B named and 3D carried; it is the Phase 5 packet's ruling-2 item.
2. **Declaration-site attribution.** The elaborator records where a node is *declared*; the
   legacy deriver attributed entry points to the design file that used them. This moves which
   `inputs/*_params.json` a key lands in. Ledger rows 12, 36; ruled expected-fix at the switch.
3. **The `model.sysml` group fallback (Slice 3B, ruling C).** A file named `model.sysml` carries
   no identity of its own, so the group takes the declaring package's name. `model_params` →
   `constraint_multi_instance_params` / `shadowed_reference_params` /
   `modeled_default_fidelity_params`. Measured and ruled in 3B.
4. **`system_design` is legacy-only.** The legacy deriver builds a group out of hierarchy data;
   the exact route has no equivalent. Already excluded by name in
   `test_exact_group_identity.py::test_a_stem_named_group_keeps_the_name_the_legacy_route_ships`.
5. **Modules and entry points the legacy route dropped.** `attr_expr_probe`'s `scaled_area`,
   `d38_caret`'s four `cell` occurrences, `unresolvable_attr_probe`'s nine concrete formulas.
   Every one is a ratified `expected-fix` row.

Everything downstream — `contracts/*.json`, `__init__.py`'s `CUSTOM_SCHEMA_TYPES`,
`pipelines/pipeline.yaml`, `IMPLEMENTATION_BACKLOG.md` — restates one of the five above. The
`package_contract.json` differences are hash-manifest restatements by construction.

## `quoted_owner_formula`: the exact route fixes generated code that does not parse

Worth naming on its own, because the legacy column is the broken one. The calc def is spelled
`'net margin'`. Legacy renders `run_net margin,` into `modules/.../net_margin.py` — a Python
identifier with a space in it. The exact route sanitizes it to `run_net_margin`. This is the
same `sanitize_name(node.calc_def_name)` hunk Slice 3D recovered, seen from the other side.

## `fusion_tea`: the customer package, in full

**Module and schema class names are unchanged** — the `modules/` name set is equal between the
two trees, which is the compatibility guarantee census row `PROD-24` requires stay fixed. No
group was renamed: `hif_driver_params`, `hif_plant_params`, and `ife_plant_params` all survive
with the same names and schema classes, which re-verifies orchestrator ruling 1's "no
customer-model group naming changes" for this model.

**Every hand-checked modeled value is unchanged.** Each value appears on both sides: `0.35`,
`5.0`, `1.0`, `3.5`, `0.9`, `0.08`, `65.0`, `2000.0`, `0.43`, `1.15`, `5000000.0`, `10.0`,
`0.1`, `40.0`, `80.0`, `6000000000.0`, `14286000.0`. Keys and group membership move; no number
does. The decisive check is the real-TEAx lane through the switched public surface: LCOE
`270.1211779380445` on live and relocated-v6 alike, unchanged from the pre-switch anchor.

**What actually changed is the per-consumer-mint collapse, which is the cutover's point.**

| | legacy | exact |
|---|---|---|
| `gain = 80.0` | two keys: `lcoe_calc__gain_in`, `recirc_calc__gain_in` | one key: `hif_plant_pkg__hif_plant__gain` |
| `thermal_efficiency = 0.43` | two keys: `lcoe_calc__…_in`, `recirc_calc__…_in` | one: `hif_plant_pkg__hif_plant__thermal_efficiency` |
| `availability = 0.9` | two keys: `lcoe_calc__…_in`, `meier_coe_calc__…_in` | one: `hif_plant_pkg__hif_plant__availability` |
| driver `beam_energy_mj = 5.0` | one key per usage, under `meier_cost__…_in` | one per modelled occurrence |

The legacy route mints one public input key per *consuming calc-usage formal*, so one modelled
value is published two or three times and an operator can set them inconsistently. The exact
route mints one key per *modelled attribute* and wires every consumer to it. Slice 3D's mutation
tests already prove the wiring: perturbing that one key moves exactly its consumers and nothing
else, structurally and at runtime, on both the C25 and C2 axes.

Two exact-only groups follow from mechanism 2 above: `hif_economics_params` (holding
`meier_capital_calc__target_factory_cost`, `meier_reactor_cost_calc__num_units`, declared in
`library/analyses/hif_economics.sysml`) and `ife_lcoe_params` (`lcoe_calc__construction_years`,
`lcoe_calc__operational_years`, declared in `library/analyses/ife_lcoe.sysml`). Legacy filed both
pairs under the design files that used them. `system_design` is legacy-only per mechanism 4.

**This is the largest customer-visible change in the whole recovery, and it is flagged to the
Phase 5 owner packet.** It changes shipped input filenames and their contents. It is not a
rule-10 stop — every key movement is mechanism 2 or the per-consumer collapse the ledger's
`expected-collapse` rows exist to describe — but it is not a detail either, and an owner
accepting this candidate should be shown the table above rather than a summary of it.

## `unresolvable_attr_probe`: exact reaches generation and the collision guard refuses

Recorded rather than smoothed over. The exact route produces the row-36 graph (10 modules, 9
entry points) and generation then refuses:

```
Module class name collision survives aliasing (grandparent collision):
'DerivedComponent_inherited_productModule' <- [...]; 'DerivedComponent_mixed_productModule' <- [...]
```

Two of the nine formulas legacy dropped alias to one module class name. The guard is the
generator's own fail-loud check working correctly on modules the legacy route never produced, and
its message names the fix (rename one scope). The fixture is a graph-level probe; no test
generates a package from it, and the corpus row is unchanged (both routes still `graph`).
Classified as a downstream consequence of ruling 1's `unresolvable_attr_probe` expected-fix, and
flagged to the Phase 5 owner packet with the rest.

## `constraint_inline` and `constraint_non_numerical`: not a switch difference

Both routes refuse identically, with the same pre-existing constraint name-safety violation
(`generated_binding_overlap` on `value`). These fixtures are graph-level constraint probes, not
package-generation fixtures. Measured on both routes so the equality is on the record rather
than assumed.
