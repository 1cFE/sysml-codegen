## Implementation Strategy

**Phasing rationale.** The design fixes the migration order and says the tree is deliberately red
between steps 1–4, green only at the end (design "Migration order"). This plan follows that order
exactly, and adds a checkpoint at every phase that *is* runnable even while the full suite is red —
so a budget-killed session resumes from checkboxes, not from guessing what state the tree is in.

The order is forced by two facts:
- `module_kind` is a **required field with no default** (design D2). The instant the flags are removed
  and the field is added (Phase 1), every construction site that hasn't set it raises a Pydantic error.
- Removing the flags makes every `src/` and `tests/` reader of `module.is_computed_attribute` /
  `module.is_aggregation` an `AttributeError` at runtime until it's rewritten.

So: model → construction → dispatch → (de-risk on real output) → tests+baselines lockstep → gates.

**Critical path.** Phase 1 → 2 → 3 make `src/` internally consistent (nothing reads a flag anymore).
Phase 3 ends with the **de-risk gate**: regenerate the committed baselines and confirm the only change
is the intended `module_kind` swap — this proves B2/B3 (the flags carried *only* kind) on real output
*before* the large test-migration edit. Phase 5 is the one atomic move the design insists on (test
files + baseline regen + comparison harnesses together). Phase 6 is the completion gate.

**First proof point.** The Phase 3 de-risk gate. Regenerating the 9 `computation_graph.json` baselines
and seeing `registry_init.py` + `baseline_yaml/` come back **byte-identical** is the earliest real-output
proof that the six dispatch rewrites reproduce today's behavior. It lands before a single test file is
touched.

**Byte-identity verification vehicle (resolves design open item).** Two committed artifact sets:
1. **Generated package** (modules/, handwritten/, schemas/, pipeline YAML, registry `__init__.py`, JSON
   templates) — must be byte-identical. Enforced by the **conformance suite** (`test_pipeline_e2e`,
   `test_graph_assembly`, `test_baselines`, `test_gen_*`), which regenerates to a temp dir and compares.
   Green suite = byte-identical. There is **no** committed generated-package tree to regenerate in place,
   so there is **no** package-timestamp churn to revert here.
2. **Committed graph baselines** (`tests/fixtures/baseline_outputs/*/computation_graph.json`, 9 of 10
   flag-carrying; `+ registry_init.py`) — regenerated by `scripts/capture_pipeline_baselines.py`. The JSON
   **intentionally changes** (`module_kind` swap); `registry_init.py` must stay byte-identical. Pipeline
   YAML baselines regenerate via `scripts/capture_baseline_yaml.py` and must stay byte-identical.

   These `computation_graph.json` files carry **no `captured_at` / timestamp** (verified) — the diff is
   clean, nothing to timestamp-filter. **Do NOT run `scripts/capture_extraction_snapshots.py`:**
   `module_kind` is a graph field, not a snapshot field; re-capturing snapshots would rewrite every
   fixture's `captured_at` for nothing (memory: *byte-identity captured_at churn*). If `git status` ever
   shows `extraction_snapshot.json` churn, you ran the wrong script — `git checkout` it and run only the
   two capture scripts named above.

**Effort estimate (resolves design open item — the epic's 7h is repriced).** ~8–10h. The logic is
mechanical but the surface is wide: 8 `src/` files + 1 new `errors.py` + 15 test `.py` files + 9 baseline
regens + comparison-harness edits + 7 new fail-loud tests. Roughly Phase 1 ≈ 0.5h, Phase 2 ≈ 0.5h,
Phase 3 ≈ 2h, Phase 4 ≈ 1.5h, Phase 5 ≈ 3–4h (the atomic move, careful), Phase 6 ≈ 0.5h. The spec's
"~3× the 7h" was against the src-only framing; against the full surface this lands near 8–10h.

**Overall validation approach.** Each phase has a checkpoint runnable in its (possibly red) state. The
full suite, INV-4 grep, mypy, and ruff are end-state gates (Phase 6). The fail-loud contract (INV-3) is
its own phase (4), passing in isolation before the bulk test migration.

## Phase 3: Dispatch — six readers + shared error helper, then de-risk on real output

### Goal
Rewrite every `src/` flag-reader as a `module_kind` dispatch (bodies unchanged for existing kinds; new
kinds raise), add the shared error constructor, then **prove byte-identity on regenerated baselines**.

### Assumption Under Test
B2/B3: each flag branch is reproducible by an enum arm returning the identical value, and no consumer
depends on the JSON key names beyond the migrated set. The de-risk gate collapses this on real output.

### Changes Required
**See design `#architecture` (Dispatch) — the per-site notes are the authority. Apply each site's exact
shape below; do NOT apply a blanket three-arm rule (design-review M1/m4).**

**New file — `src/sysml_codegen/generation/errors.py`** (design Component Overview; helper *imports*
`CodeGenerationError`, which is **defined in `orchestration/pipeline_context.py:48`** and re-exported via
`generation/__init__.py` — do not hunt for it under `generation/`):
- [ ] Create `unrenderable_module_kind_error(module, seam_name)` returning a `CodeGenerationError` with
  the design D4 message form:
  ```python
  def unrenderable_module_kind_error(module, seam_name):
      # Lazy import mirrors the proven pattern at cli/__init__.py:195 (avoids any import cycle).
      from sysml_codegen.generation import CodeGenerationError
      return CodeGenerationError(
          f"Module {module.name!r} (module_kind={module.module_kind.value!r}) reached the "
          f"{seam_name} seam, which has no rendering for this kind yet (wired in Item 7). "
          f"Refusing rather than mis-rendering it as a calculation."
      )
  ```
- [ ] Each seam imports it: `from sysml_codegen.generation.errors import unrenderable_module_kind_error`
  (fall back to a function-local import if a file hits a circular import).

**Seam 1a — `_get_python_path` (`cli/__init__.py:150–161`), three-arm.** Rekey the existing
computed/agg/else chain; add the raise:
- [ ] `if module.is_computed_attribute:` → `if module.module_kind == ModuleKind.FORMULA:` (body unchanged)
- [ ] `elif module.is_aggregation:` → `elif module.module_kind == ModuleKind.AGGREGATION:` (body unchanged)
- [ ] `else:` (calc body) → `elif module.module_kind == ModuleKind.CALCULATION:` (body unchanged)
- [ ] add `else: raise unrenderable_module_kind_error(module, "python-path")`

**Seam 1b — `_raw_source_name` (`cli/__init__.py:164–174`), TWO-arm — NOT three (design-review M1).**
Today aggregation shares the calc `else`. After:
- [ ] `if module.is_computed_attribute:` → `if module.module_kind == ModuleKind.FORMULA:` (return `{qn}::{name}` unchanged)
- [ ] the shared `return module.calc_def_qualified_name or module.name` line becomes the
  **`AGGREGATION`+`CALCULATION`** arm:
  ```python
      if module.module_kind in (ModuleKind.AGGREGATION, ModuleKind.CALCULATION):
          return module.calc_def_qualified_name or module.name
      raise unrenderable_module_kind_error(module, "raw-source-name")
  ```

- [ ] `_check_duplicate_output_paths` (`cli/__init__.py:177–222`) needs **no logic change** — it now

**Seam 2 — `generate_registry` (`registry.py:220–226` split).** Repartition by kind and add a guard pass:

## Risk Management

**See design `#potential-risks`.** Phase-specific:
- **Missed dispatch/test site (silent).** Mitigation: Phase 6 INV-4 grep is exhaustive over src+tests;
  Phase 3 de-risk gate + Phase 5 conformance suite catch any behavior shift for existing kinds.
- **Baseline diff carries an unintended change.** Mitigation: Phase 3 spot-check against design
  `#baseline-diff-spec` (two-out / two-in-plus-null); a changed `registry_init.py` or `.yaml` is a bug.
- **Registry seam drops a constraint module silently (fails open).** Mitigation: Phase 4
  `test_registry_seam_refuses_constraint` at the seam entry (design-review M2) — verified to fail if the
  guard-pass is deleted.
- **`_raw_source_name` mis-migrated as three-arm.** Mitigation: Phase 3 Seam 1b spelled out as two-arm
  (AGGREGATION joins CALCULATION); the byte-identity gate would abort on a divergence.
