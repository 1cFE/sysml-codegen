# R3 rows: how each closed in Item 2a

Written in Phase 3 (2026-10-18). One line per R3 row routed to 2a. Rows that finish in a later phase say so. "Rule criterion" is spec § R3 rows (D11): a rule needs a refusal branch whose reaching contexts can be stated, using facts agentic-mbse already extracts, with no heuristic. Every refusal named here is recorded in `tests/expectations/subset_profile/disagreements.json`, and every case named is either an agentic-mbse packaged case (`src/agentic_mbse/sysml/subset_cases/`) or a codegen-home case (`tests/fixtures/subset_profile/`).

## Decided by the rule criterion

- **ES-002 (constraint binds a calc usage's input): reproduced gap.** The refusal (`SI_OCCURRENCE_MISSING`, `elaboration/occurrence.py:180`) reaches far more than the recorded shape: any reference into a feature owned by a calc usage, an item usage or an attribute usage, except a calc output, which `_calculation_output_producers` exempts. Which references reach it depends on codegen's `_reference_address` and `_calculation_output_producers`; no shared fact carries either, so no rule. Cases: the binding (`candidate-es-002__constraint_binds_calc_input__binding_value`), four other reaching shapes (`…attribute_reads_calc_input…`, `…calc_binds_calc_input…`, `…item_usage_feature…`, `…attribute_usage_feature…`), the admitted neighbor in codegen's home (`candidate-es-002__constraint_binds_calc_output__binding_value`, generates), and fixture `usage_owner_calc_usage_leaf`. The `SiteReason` lands in P5.
- **ES-008 (nested named subsets each redefining a value): reproduced gap.** Refused (`SI_REDEFINITION_INVALID`) when two or more sibling subsets each redefine the same nested value: three spellings (`…nested_named_subset…`, `…nested_named_subset…__single_rack`, `…sibling_subsets_redefine…`). A single redefinition, an outer redefinition and plain nesting all generate (codegen-home controls `…one_subset_redefines…`, `…outer_redefinition…`, `…plain_nesting…`). Which writer is chosen is codegen's value-writer selection, not a shared fact, so no rule. `SiteReason` in P5.
- **ES-009 (composition by subsetting a top-level usage): reproduced gap.** Narrow: subsetting an untyped top-level usage and then reading its own attribute is refused (`SI_OCCURRENCE_MISSING`, `elaboration/elaborate.py:2345`), at a nested part and at a root part. Typed subsetting, nested untyped subsetting and a direct package read all generate (codegen-home controls). A reference through a `ref part` reaches a neighboring `SI_OCCURRENCE_MISSING` site and is recorded with this row (`…reference_through_ref_part…`). The reach depends on codegen's occurrence anchoring, so no rule. `SiteReason` in P5.
- **CALC-DEF-BARE-RESULT: reproduced gap.** The condition is codegen's extractor finding zero output attributes (`extraction/extractor.py:91-230`), not the bare expression as such: a calc def that declares `return r : Real;` and then gives a bare expression is refused the same way (`…declared_return`), and so is one nothing reads (`…unused`), so the refusal is model-wide. What the extractor reads as an output is not a shared fact, so no rule. Cases: arithmetic, `max`, the two new spellings, and the four expression-rule cases whose pairs are unobservable for this reason; fixtures `anonymous_return` and `zero_output_calc` fall under it too. `SiteReason` in P5.

## Closed with cases, no rule needed

- **ES-010 refusal side (String reaching an entry-point input): reproduced gap with a codegen-owned reason.** Entry-point membership is an output fact codegen owns (ADR 0007), so no shared rule. Paths: a String bound to a calc input (`candidate-es-010-refusal__string_to_calc_input__binding_value`) and a String usage literal (`…string_usage_literal…`) are both refused at projection (`SI_RENDERING_COLLISION`); fixture `subset_profile_occurrence_seed/es010_refused_string_calc_input` too. The third path, a calc def's String library default left unbound (`…string_library_default…`, codegen home), **generates**: it becomes a `str` entry point whose default is null, so the `"liter"` default does not reach the output. That is a silent-loss finding for P4's String family; the policy is RG-2.
- **ES-011 (arithmetic on a named calc return): reproduced gap.** `c.r * k` with `return r` is refused `SI_EDGE_DANGLING` (`…return_result_arithmetic…`); the `out attribute r` spelling generates (codegen-home control). The refusal depends on how codegen wires a return to its output channel. `SiteReason` in P5.
- **DEEP-QUALIFIED-WIRING: reproduced gap, as the spec row says.** The minimal case (`deep-qualified-wiring__qualified_reference`, codegen home) is refused `SI_OCCURRENCE_MISSING`; the feature-chain spelling generates. Fixture `deep_cross_scope_probe` and ten other corpus fixtures with consumer-domain refusals are recorded under this row. Implementation stays sysml-codegen [DEEP-QUALIFIED-OUTPUT-WIRING].
- **PUSH-DOWN-AGG-PROFILE-LITERAL-SHAPE: admitted.** `attribute total : Real = sum(5.0);` generates as a computed-attribute module (seam `calc_compilability` = `fully_compilable`, output `total`), and so does `sum(modules.cost) + 5.0` (codegen-home cases `push-down-literal-shape__*`). The row goes to Item 3 with these cases.
- **PUSH-DOWN-HIER-PROFILE-REDEF-PRECEDENCE: published.** Which value wins: the design-level override. With a definition default of 0.2, a specializing definition's default of 0.3 and a usage-level `= 0.35`, the generated value is 0.35 from the occurrence override, whether the override is written as a feature chain (`:>> driver.efficiency = 0.35`) or as a nested redefinition (`part :>> driver { :>> efficiency = 0.35; }`). Pinned by seam `attr_value` in codegen-home cases `push-down-redef-precedence__*`. Turning this into a shared fact is Item 3's.
- **PUSH-DOWN-HIER-PROFILE-AMBIG-INHERITED-ATTR: published, and the row's premise is false.** The backlog row assumed codegen picks the sorted-first of two incomparable typings. It does not: a part usage typed `A, B`, where both redefine an inherited attribute, is refused (`SI_REDEFINITION_INVALID`, "incomparable exact user-definition typings"). The screen reports the model incomplete, not refused. Case `candidate-ambiguous-typing__incomparable_typings__part_usage`; fixtures `occurrence_multiplicity_incomparable` and `subset_profile_occurrence_seed/f1_abort_incomparable_typings` show the same. Item 3 should start from "refused", not "sorted-first".

## Contract changes Phase 3 made

- **calc-owned-assertion widened to every owner codegen cannot attach (rule criterion holds).** Phase 2 handed over a constraint owned by an item def. Codegen's owner map is closed (`elaboration/elaborate.py:800-827`: part def, part usage, calc def, package, requirement def), so the refusing contexts can be stated from the owner's kind. New context `unmapped_owner_kind`, new owner kind `requirement_definition` in agentic-mbse's facts, five record cases (an item def owner in both shapes, and item usage, attribute def and constraint def owners) and a requirement-def control that generates. The refusal is model-wide. Not RG-1: it changes what the screen reports, not what the generator does.
- **Three spellings the screen refuses as `constraint-predicate/blocked_predicate` that the generator refuses with another code: not narrowed, recorded.** `assert constraint bare;` and a `Constraints::ConstraintCheck`-typed constraint fail with `SI_EDGE_DANGLING` ("constraint profile selected an unrecognized definition UUID"). The mixed-unit sum fails because its operand is quantity-typed (`ISQBase::LengthValue` is an unsupported exact type), not because the units differ: the same-unit sum is refused the same way. The default to narrow (spec L3-6) is for a screen refusal of a model the generator builds; here both refuse, and narrowing would make the screen silent on a refused model. The generator fails closed, so nothing looks semantically wrong, and no `kerml-expert` check or RG-1 entry was made. Each is a `code_unmapped` disagreement (`reproduced_gap`). A `SiteReason` names the refusing site but cannot map the pair, because `REASON_MAPPING` maps screen reasons to generator codes (corrected in P5); their sites are tail rows. The cases live in codegen's home as `blocked-predicate-unmapped-code__*`, because the records cannot cite a refused case that does not show the mapped code.
- **The anonymous `assert positive;`: parity fixed, now a recorded `code_unmapped` disagreement.** agentic-mbse's occurrence copy now keys constraint attachments by element ID, as codegen's `_index_constraint_associations` does (`elaboration/elaborate.py:592-604`), so occurrence parity holds on it. The screen refuses it as `blocked_predicate`; the generator refuses it `SI_ID_UNSTABLE`. Case `blocked-predicate-unmapped-code__anonymous_assert_by_reference` (codegen home, for the same reason as the three spellings). Parity covers it through `test_occurrence_parity.py`, which runs every case in either home.

## New family found: anonymous declarations

- **Anonymous inline constraints: reproduced gap; a rule candidate for the owner.** `assert constraint { … }` and `constraint { … }` with no name are refused `SI_ID_UNSTABLE` while the screen is silent (`candidate-anonymous-constraint__*`). The same code refuses anonymous constraints in fixtures `constraint_name_collision_probe` and `constraint_occurrence_demand/anonymous`, and an anonymous part def and part usage in `constraint_occurrence_demand/cycle_indirect` and `elab_identity_collision_probe`. A model-wide "anonymous declaration codegen must index" rule looks stateable from the declaration's name alone, but which declarations codegen indexes is not yet pinned down, so it is not added here.

## Closed in Phase 5 (site reasons and head sites, 2026-10-19)

- **Site reasons for every R3-row gap.** Each refusing site now passes its own `SiteReason`, each case that reaches it names it as a witness, and neutralizing the site changes exactly those cases (`tests/expectations/subset_profile/mutations.json`). ES-002 `occurrence_containment_unanchored` (`elaboration/occurrence.py`, `build_containment_address`); ES-008 `elaboration_value_writers_incomparable` (`_require_one_writer`); ES-009 `elaboration_owner_address_target_missing` (`_resolve_semantic_reference`), and `occurrence_containment_step_missing` for the reference through a `ref part` (`OccurrenceIndex.resolve_address`); DEEP-QUALIFIED-WIRING `elaboration_calculation_output_unproduced` (`_resolve_calculation_output`); ES-011 `elaboration_feature_declaration_unindexed` (`_feature_python_type`: a named calc return is not in the element index); ES-010 refusal side `projection_default_non_numeric` (`elaboration/project.py`, `_float_default`); CALC-DEF-BARE-RESULT `extraction_calc_def_no_output` (`extraction/extractor.py`). ES-002 and ES-009 both refuse `SI_OCCURRENCE_MISSING` and are told apart by reason alone (`test_site_reasons.py`), so B6 holds and no recorder observable was needed. The ES-009 neighbor and ES-011 sites joined the head (`matrix_row` filled), since P3 recorded their cases under those rows.
- **ES-002 broad shape: no rule; reproduced gap with this boundary.** Refused: a reference whose leaf is a feature of a calc usage (an input, or an attribute the usage declares), of a calc def that is not its return or an `out` attribute (`c.t`), of an item usage, or of an attribute usage; also a read through a part nested in an item usage (`it.rk.cap`). Admitted: a calc usage's return or `out` attribute (`c.r`, `p.c.r`). The criterion fails for two reasons. First, the exemption is codegen's output registry (`_calculation_output_producers`), and no shared fact says whether a reference's leaf is a declared output. Second, the refusing site and code depend on the path codegen's `_reference_address` walks: a direct read refuses at `build_containment_address` (`occurrence_containment_unanchored`), the same read through a part segment (`p.c.v`) refuses at the ES-009 owner-address site (`elaboration_owner_address_target_missing`), and `it.rk.cap` ends `SI_EDGE_DANGLING` from graph validation. Cases (codegen home): `candidate-es-002__calc_input_through_part__attribute_value`, `…__calc_definition_intermediate__…`, `…__part_inside_item_usage__…`, control `…__calc_output_through_part__…` (generates), beside P3's five. For Item 5's guidance: "read a calc usage only through its outputs; do not read features of item or attribute usages from outside them".
- **Anonymous declarations codegen must index: no rule; reproduced gap with this boundary.** The condition is a declaration with no qualified name, which includes a named declaration inside an anonymous one. Refused `SI_ID_UNSTABLE` at the identity boundary (`elaboration/identity.py`): part usages (instantiated, template-only or at package level), part defs, nested packages, calc usages, constraint usages (inline or `assert` by reference) and requirement defs. Refused with other codes: an anonymous calc def, or a calc def with an anonymous `in` parameter (`SI_ID_MISSING`, `_index_calculation_payloads`), an anonymous constraint def, or a constraint inside an anonymous item def (`SI_EVIDENCE_INCOMPLETE`, relayed `evidence_resolved_target_missing`). Admitted: anonymous attribute, item, port, action and occurrence usages and their definitions, and an anonymous attribute inside a calc def. The criterion fails because which QN-less declarations reach an identity check is decided by filters inside codegen's Feature-wide loops (`elaborate.py`, `occurrence.py`, `expression_evidence.py`; 64 `declaration_id_for` calls), not by a closed list of kinds, and the code differs by owner (the constraint case above). A metatype list on the screen side would copy those filters, which is the heuristic the criterion excludes. On the screen side, the occurrence copy aborts on the part, package and calc-usage shapes, so the verdict is `incomplete` with no refused finding; the constraint and requirement-def shapes read `clear`. Cases (codegen home): `anonymous-declaration__part_usage`, `…__calc_usage`, `…__calc_definition`, `…__requirement_definition`, `…__package`, `…__named_part_in_anonymous_action`, controls `…__attribute_usage` and `…__item_usage` (both generate), beside P3's `candidate-anonymous-constraint__*`. For Item 5's guidance: "name every part, package, calc, constraint and requirement declaration, including those inside unnamed ones".
- **PUSH-DOWN-EXPR-PROFILE-CHAIN-SEGMENTS: verdicts for Item 3.** `binding_source.py:236` (an index in a redefinition's chain) and `:243` (a non-Feature segment) are unreachable under SysIDE 0.8.4: `attribute :>> rack#(1).cap = 5.0;` is a parse error, and SysIDE types `chaining_features` as `LazyIterator[Feature]`. Both rows are now role `environment` and leave the head. `binding_source.py:251` and agentic-mbse `reference_use.py:545, :557, :594, :618` stay `unknown`: an unresolved name is a SysIDE reference-error at load, and a chain inside an anonymous owner is refused `SI_ID_UNSTABLE` (generator) or left incomplete (screen) before the chain is read. No model reached them. The attempts are in each row's note.
- **PUSH-DOWN-AGG-PROFILE-SUM-SHAPE: verdicts for Item 3.** `elaboration/project.py`'s sum-arity raise is reachable: `attribute t : NumericalValue = sum();` is refused at projection (`PROJECTION_FAILED` + `SI_SNAPSHOT_INVALID`, reason `projection_sum_argument_count`), while the screen admits it. SysIDE refuses two or more positional arguments itself, and an empty `sum()` assigned to a `Real` is a SysIDE type error, so zero arguments with a `NumericalValue` target is the one reaching shape. A second finding: `sum((a, b))` in a computed attribute value is refused `SI_EDGE_DANGLING` (the sequence literal becomes unsupported expression IR; `elaboration/graph.py`), while in a calc def output the same call is a manual stub. Cases `push-down-sum-shape__zero_arguments` and `…__sequence_argument` (codegen home), each a `reproduced_gap` under this row. The code `SI_SNAPSHOT_INVALID` is misleading on a live model; changing it was not in scope.
- **O8 (plain exceptions among head sites): none.** Every head site raises a coded error or a `CompilationError` (the stub family, settled in P4), so no head site is an RG-1 candidate under O8.

## Tail sites, no R3 row (Phase 6, 2026-10-19)

Phase 6 gave every remaining public site a reason and a witness. None of these shapes has an R3 row and Item 2a attempted no rule for them, so each is a disagreement in `disagreements.json` and stays there for Item 3 or Item 5 to take up.

- **Codegen-owned output naming (14 cases, `codegen_owned`).** Two distinct SysML names that sanitize to one public name are refused before writing: module and schema paths, registry class names, entry-point keys and schema fields, module, channel, parameter and alias names, predicate function names, a constraint input named like the wrapper's own binding (`value`), and a package-scoped group with no package name. Cases `output-naming__*` and `constraint-naming__*`. These are codegen's own facts (ADR 0007), so no shared rule describes them. For Item 5's guidance: "do not give two declarations names that differ only in punctuation, spacing or case".
- **Model shapes codegen refuses and the screen is silent on (29 cases, `reproduced_gap`).** Calc def identity (a duplicate qualified name; an anonymous parameter); deep literal overrides through a `ref part` or onto a computed value; calc usages typed by a library calc def, untyped, or typed only by subsetting; constraints that inherit their definition by subsetting, or are untyped and bind an input; calc def `out part` parameters; attributes read in expressions with no owned ScalarValues type (subsetting only, untyped, quantity-typed); a binding of an undeclared input; references to library constants, to a nested feature through a bare import, to a calc def result through the definition with two producers, through a part with several occurrences, or anchored at a part def outside or twice in the lineage; `null` and `*` literal bindings; one feature redefining two unrelated features; a part usage typed by two unrelated part defs; a calc def reading a package attribute; an anonymous return; an untyped or quantity-typed calc def parameter. Cases are named after each shape in `tests/fixtures/subset_profile/`.
- **agentic-mbse shared limits (3 packaged cases, `reproduced_gap`).** An expression nested past the 100-level traversal depth, in a value and in a constraint predicate, and a feature chain whose head is a conditional. The generator refuses with the relayed evidence reason; the screen's verdict is incomplete.
- **O8: one conversion.** `_typed_definition`'s plain `ValueError` became `SI_TYPE_INVALID` (`evidence/changed-outputs.md` § P6). No RG-1 candidate: every other tail site already raised a coded error, a `CompilationError` relayed with a code, or a `TypeError` that `validate()` turned into `SI_EDGE_DANGLING`.
