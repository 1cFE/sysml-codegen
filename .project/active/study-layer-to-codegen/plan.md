## The Point

A modeling project that uses sysml-codegen and teax must get the whole study capability by installing sysml-codegen and running `sysml-codegen install-commands`. The capability is the `run-study` skill (skill file, runbook, record template), a study-policy template, and the tools those steps call. The project must then be able to run a study from intake to a committed record, and hand it to a second agent, with nothing copied from fusion-tea. Today the capability exists only inside fusion-tea, and nothing installs it.

- [OWNER] (epic header, 2026-10-06): the study layer ships from sysml-codegen. [OWNER-VERBATIM] "ported and generalized … installed like everything else".
- [AGENT] (orchestrator, uncontested): the bar is a working capability in a fresh target, not copied files.
- [NEED] fusion-tea loses no information. Every fusion-specific line removed from the shipped text has a fusion-tea home before the removal merges.
- [INFERRED] The move is byte-faithful except for the closed list B1–B13, which is ADR-0007's lesson. SC12's parity script proves it.
- It serves P-001: "the study layer owns exploration and decisions" over the generated package.

**Parallelism.**

- Phase A runs beside Phases 1–5, in its own worktree, by a separate implementer.
- The sysml-codegen phases run one at a time. They share one worktree, one index and one test tree.
- Phase 6 is the only sysml-codegen phase that needs Phase A.
- O4 can start as soon as Phase 5 is committed, beside Phase 6.

**Critical path.** 1 → 2 → 3 → 4 → 5 → 6 → O1, O2, O3. Phase A is off the critical path unless it outlasts Phases 1–5.

**First proof point.** Phase 1's first test runs the neutral station model through the stock teax study lifecycle. The model is generated by this branch, and the test expects `required_flow` 0.24, `annual_cost` 192.0 and `pump_fit` satisfied. If that fails, KB4 is false and verify and `CANDIDATE` cannot be reached on the fixture. Then cut 2 applies, and the orchestrator decides before Phase 2 starts.

**Why this order.**

- KB4 goes first. It is the design's first de-risk item, and it is the cheapest proof of whether cut 2 is forced.
- The port is next, because every later phase imports it. It ends with `indicators` on `synthetic_pkg` matching fusion-tea's layout, which is the design's third de-risk item.
- The fixture comes before integrate, because integrate's tests copy the fixture.
- Parity runs right after integrate. An unlisted difference (KB3) then surfaces before the text and installer work, not at the end.
- The text comes after integrate, because the guide-contract test holds the guide to integrate's final slugs, flags and declaration keys.
- The installer goes last. It is the only part that needs Phase A, and it installs the files Phase 5 writes.
