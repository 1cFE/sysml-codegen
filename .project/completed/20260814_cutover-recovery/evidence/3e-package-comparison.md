# Slice 3E — generated-package comparison, legacy vs exact

- **Measured:** 2026-08-11, at the Slice 3E authority switch
- **Method:** for each fixture, generate twice into clean trees from the same model — once
  through the switched public `run_codegen` (exact), once through
  `tests/helpers/legacy_route.generate_via_legacy_route` (legacy) — then compare every file in
  both trees byte for byte. Not a sampled comparison: `rglob("*")` over the whole package.
- **Rule:** every difference maps to a ratified ledger row or a recorded slice mechanism, or it
  is unexplained. **Unexplained count: zero**, and that is what the per-fixture tables below
  show — not a claim that six summary sentences cover every hunk.

## The six difference mechanisms, each named once

*(Was "five" until the Slice 3E audit, F2. Mechanism 6 was always present in the measured diffs
and correctly classified per fixture against ledger rows 26 and 37; the summary list was what
omitted it. The rule-10 claim below is stated as what the per-fixture table actually shows.)*

1. **Provenance comments.** The live route records absolute checkout paths, the v6 route the
   portable `root-N/<relpath>` referent. Reaches generated bytes only as `SysML Source:` lines.
   The residual Slice 3B named and 3D carried; it is the Phase 5 packet's ruling-2 item.
2. **Declaration-site attribution.** The elaborator records where a node is *declared*; the
   legacy deriver attributed entry points to the design file that used them. This moves which
   `inputs/*_params.json` a key lands in. Ledger rows 12, 36; ruled expected-fix at the switch.
3. **The `model.sysml` group fallback (Slice 3B, ruling C).** A file named `model.sysml` carries
   no identity of its own, so the group takes the declaring package's name. `model_params` →
   `constraint_multi_instance_params` / `shadowed_reference_params` /
   `modeled_default_fidelity_params`. Measured and ruled in 3B.
4. **`system_design` is legacy-only.** The legacy deriver builds a group out of hierarchy data;
   the exact route has no equivalent. Already excluded by name in
   `test_exact_group_identity.py::test_a_stem_named_group_keeps_the_name_the_legacy_route_ships`.
5. **Modules and entry points the legacy route dropped.** `attr_expr_probe`'s `scaled_area`,
   `d38_caret`'s four `cell` occurrences, `unresolvable_attr_probe`'s nine concrete formulas.
   Every one is a ratified `expected-fix` row.
6. **Entry-point keys move from consumer-scoped and definition-scoped naming to the modelled
   attribute's declaration path.** Legacy names an entry point after the *consuming calc-usage
   formal* (or, on `wi014_toy`, after the part *definition*); the exact route names it after the
   modelled attribute that supplies it. `toy_plant__Toy_Plant__plant_budget` →
   `toy_plant__demo_plant__plant_budget` (ledger row 37, *"source keys now use concrete
   occurrences and modeled attributes"*); the same shape plus a new channel on `retype_model`
   (row 26); and the whole fusion_tea key table below. Where several formals consume one
   attribute this also collapses N keys into one; where one formal consumes it, it is a rename
   only. Same mechanism either way.

Everything downstream — `contracts/*.json`, `__init__.py`'s `CUSTOM_SCHEMA_TYPES`,
`pipelines/pipeline.yaml`, `IMPLEMENTATION_BACKLOG.md` — restates one of the six above. The
`package_contract.json` differences are hash-manifest restatements by construction.

## `quoted_owner_formula`: the exact route fixes generated code that does not parse

Worth naming on its own, because the legacy column is the broken one. The calc def is spelled
`'net margin'`. Legacy renders `run_net margin,` into `modules/.../net_margin.py` — a Python
identifier with a space in it. The exact route sanitizes it to `run_net_margin`. This is the
same `sanitize_name(node.calc_def_name)` hunk Slice 3D recovered, seen from the other side.

## `fusion_tea`: the customer package, in full

**Module and schema class names are unchanged** — the `modules/` name set is equal between the
two trees, which is the compatibility guarantee census row `PROD-24` requires stay fixed. No
group was renamed: `hif_driver_params`, `hif_plant_params`, and `ife_plant_params` all survive
with the same names and schema classes, which re-verifies orchestrator ruling 1's "no
customer-model group naming changes" for this model.

**Every hand-checked modeled value is unchanged.** Each value appears on both sides: `0.35`,
`5.0`, `1.0`, `3.5`, `0.9`, `0.08`, `65.0`, `2000.0`, `0.43`, `1.15`, `5000000.0`, `10.0`,
`0.1`, `40.0`, `80.0`, `6000000000.0`, `14286000.0`. Keys and group membership move; no number
does. The decisive check is the real-TEAx lane through the switched public surface: LCOE
`270.1211779380445` on live and relocated-v6 alike, unchanged from the pre-switch anchor.

**What changed is how every entry-point key is named — mechanism 6, enumerated exhaustively.**

*(Rewritten after the Slice 3E audit, F1, which found one shipped key rename this section had
omitted. The fix is not to add one row: it is to enumerate every key delta so a second omission
is impossible to hide. Legacy publishes **31** keys, the exact route **27**, sharing **13**.)*

Read the whole table as one mechanism. Legacy names an entry point after the *consuming
calc-usage formal*; the exact route names it after the *modelled attribute* that supplies it.
Where several formals consume one attribute the rename also collapses N keys into one; where a
single formal consumes it, it is a rename only. Consumer sets are identical on both routes for
every row — no entry point was lost or gained, only re-keyed.

**A. Several consumers → one key (the collapse).**

| Modelled value | legacy keys | exact key | consumers, both routes |
|---|---|---|---|
| `gain = 80.0` | `…__gain` **and** `lcoe_calc__gain_in`, `recirc_calc__gain_in` | `…__gain` alone | `lcoe_calc.gain_in`, `recirc_calc.gain_in`, `viability.gain_in` |
| `thermal_efficiency = 0.43` | `lcoe_calc__…_in`, `recirc_calc__…_in` | `hif_plant_pkg__hif_plant__thermal_efficiency` | `lcoe_calc`, `recirc_calc` |
| `availability = 0.9` | `lcoe_calc__…_in`, `meier_coe_calc__…_in` | `hif_plant_pkg__hif_plant__availability` | `lcoe_calc`, `meier_coe_calc` |

Note the `gain` row precisely: legacy published the modelled key **and** two per-consumer copies
of the same value, so an operator could set them inconsistently. The exact route publishes one.

**B. One consumer → one key (rename only, no collapse).** Ten rows, every one a single consumer

**C. The constraint threshold — the key the audit caught, classified against the graph.**

| legacy key | exact key | sole consumer, both routes |
|---|---|---|
| `hif_plant_pkg__hif_plant__viability__81ddf10fb1d1749b__threshold` (`system_design`) | `hif_plant_pkg__hif_plant__viability__threshold` (`ife_plant_params`) | `hif_plant_pkg__hif_plant__viability__81ddf10fb1d1749b.threshold` |

**Verified against the graph before classifying, and the obvious reading turned out to be wrong.**
It is tempting to file this with the collapse family — a per-consumer hash-suffixed mint folding
into a clean semantic key. It is not. Measured on both routes: there is **exactly one consumer on
each side, and it is the same module with the same formal**. Nothing collapsed. The constraint's
disambiguating id `81ddf10fb1d1749b` is **retained identically on both routes** in the module id
and in the evaluation channel (`…viability__81ddf10fb1d1749b__evaluation`); it is dropped only
from the *entry-point key*.

So this is family B, a one-to-one rename, and the mechanism is the ordinary one: legacy built the
key from the **consuming constraint module's id** (which carries the disambiguator), the exact
route builds it from the **modelled attribute's declaration path** (`viability::threshold`). Same
mechanism 6 as every row above; the hash is incidental to it, not the subject. The group move
`system_design` → `ife_plant_params` is mechanism 4 plus mechanism 2 — `system_design` does not
exist on the exact route, so the key had to land in a real group, and declaration-site attribution
chose it. Value `10.0`, unchanged.

**One consequence worth the owner's attention, flagged to the Phase 5 packet.** Dropping the
disambiguator means two constraint usages with the same name under one owner would mint the same
`…__threshold` key. No model in the 37-fixture corpus has that shape and no failure was measured,
so this is a question for the packet, not a defect claim — but the exact route keeps the
disambiguator everywhere *except* the input key, which is the surface an operator edits.

**D. Group moves, key unchanged (10).** Mechanism 2, declaration-site attribution:
`chamber__blanket_energy_multiple`, `chamber__yield_cost_constant`, `target_factory__cost_per_target`
(`ife_plant_params` → `hif_plant_params`); `driver__efficiency`, `driver__energy`,
`driver__lifetime_shots` (`ife_plant_params` → `hif_driver_params`); `lcoe_calc__construction_years`,
`lcoe_calc__operational_years` (`ife_plant_params` → `ife_lcoe_params`);
`meier_capital_calc__target_factory_cost`, `meier_reactor_cost_calc__num_units`
(`hif_plant_params` → `hif_economics_params`). The last four are why `hif_economics_params` and
`ife_lcoe_params` exist at all; both hold entry points declared in `library/analyses/`.

**E. One definition-scoped → occurrence-scoped rename.** `hif_driver__HIF_Driver__efficiency` →
`hif_driver__hif_driver_instance__efficiency`, same sole consumer. The `wi014_toy` shape
(ledger row 37) appearing in the customer model.

**The enumeration is complete: 18 legacy-only + 14 exact-only + 10 group moves = every delta**,
and every legacy-only key is matched to an exact-only or shared key by identical consumer set.
There is no second unlisted rename.

**This is the largest customer-visible change in the whole recovery, and it is flagged to the
Phase 5 owner packet.** It changes shipped input filenames and their contents. It is not a
rule-10 stop — every key movement is mechanism 2, 4 or 6 above, enumerated exhaustively — but it
is not a detail either, and an owner
accepting this candidate should be shown the table above rather than a summary of it.

## `unresolvable_attr_probe`: exact reaches generation and the collision guard refuses

Recorded rather than smoothed over. The exact route produces the row-36 graph (10 modules, 9
entry points) and generation then refuses:

```
Module class name collision survives aliasing (grandparent collision):
'DerivedComponent_inherited_productModule' <- [...]; 'DerivedComponent_mixed_productModule' <- [...]
```

Two of the nine formulas legacy dropped alias to one module class name. The guard is the
generator's own fail-loud check working correctly on modules the legacy route never produced, and
its message names the fix (rename one scope). The fixture is a graph-level probe; no test
generates a package from it, and the corpus row is unchanged (both routes still `graph`).
Classified as a downstream consequence of ruling 1's `unresolvable_attr_probe` expected-fix, and
flagged to the Phase 5 owner packet with the rest.

## `constraint_inline` and `constraint_non_numerical`: not a switch difference

Both routes refuse identically, with the same pre-existing constraint name-safety violation
(`generated_binding_overlap` on `value`). These fixtures are graph-level constraint probes, not
package-generation fixtures. Measured on both routes so the equality is on the record rather
than assumed.
