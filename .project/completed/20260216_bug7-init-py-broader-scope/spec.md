## Business Goals

### Why This Matters

Generated Python packages should be complete and import-ready without manual fixups. The codegen pipeline currently creates 6 top-level subdirectories (`schemas/`, `modules/`, `handwritten/`, `pipelines/`, `inputs/`, `tests/`) but never writes `__init__.py` into them. This was flagged as a FAIL (broader scope) in both e2e_attr_expr_v3 and solar_battery_v3 E2E validation runs (plan sections 2.6 and 4.9).

Every missing `__init__.py` is a potential import failure, IDE navigation issue, or manual workaround the consumer must apply. Closing this eliminates the last remaining Bug 7 finding from the COST-PATTERN validation.

### Success Criteria

- [ ] `find generated/<pkg> -type d` shows `__init__.py` in every directory — zero manual additions needed
- [ ] Bug 7 status in E2E validation changes from FAIL (broader scope) to PASS

### Priority

Low complexity bug fix. Part of the COST-PATTERN validation bug-fix tail. Blocks the Phase 6 gate decision (Bug 7 row in the per-bug matrix).

## Problem Statement

### Current State

`_setup_output_directories()` at `src/sysml_codegen/cli/__init__.py:98-110` creates 6 subdirectories but never writes `__init__.py` into any of them:

- `schemas/` — always missing
- `modules/` — gets `__init__.py` incidentally when nested namespace subdirs exist, but not reliably
- `handwritten/` — same incidental behavior as `modules/`
- `pipelines/` — always missing
- `inputs/` — always missing
- `tests/` — always missing

The top-level `output_path/` gets its `__init__.py` via `_generate_registry()`, and intermediate namespace dirs (e.g., `modules/solarbatterydesign/`) get theirs via `_ensure_package_init_files()`. But the 6 top-level subdirectories fall through the gap.

### Desired Outcome

All generated directories are proper Python packages with `__init__.py` files. The fix MUST be in `_setup_output_directories()` so it applies uniformly to all codegen runs (fresh, `--overwrite`, `--smart-regen`).

---

## Scope

### In Scope

- Add `__init__.py` stub creation to `_setup_output_directories()` for 6 subdirectories
- Unit test for `_setup_output_directories()` verifying all subdirs have `__init__.py`
- Integration test assertion in existing pipeline test verifying subdirectory `__init__.py` existence

### Out of Scope

- Changing the top-level `__init__.py` (registry) generation
- Changing `_ensure_package_init_files()` behavior
- Changing content of existing namespace `__init__.py` stubs
- Any changes outside `src/sysml_codegen/cli/__init__.py` and test files

### Edge Cases & Considerations

- **`--smart-regen` mode**: Directories already exist; the `not init_file.exists()` guard MUST prevent overwriting custom content
- **`--overwrite` mode**: Directory is cleared first, then `_setup_output_directories()` runs fresh — fix applies naturally
- **`output_path/` exclusion**: MUST NOT create a stub `__init__.py` in `output_path/` — that file is generated later by `_generate_registry()` with substantial registry content
- **`pipelines/` and `inputs/`**: Contain YAML/JSON, not Python — include `__init__.py` anyway for consistency and tooling support

---

## Requirements

### Functional Requirements

> All requirements derived from E2E validation findings and root-cause research.

1. **FR-1**: `_setup_output_directories()` MUST create `__init__.py` in all 6 subdirectories: `schemas/`, `modules/`, `handwritten/`, `pipelines/`, `inputs/`, `tests/`
2. **FR-2**: `_setup_output_directories()` MUST NOT create `__init__.py` in `output_path/` (reserved for registry generation)
3. **FR-3**: Created `__init__.py` files MUST contain a bare docstring stub (e.g., `"""Generated package."""\n`), matching the existing pattern from `_ensure_package_init_files()`
4. **FR-4**: `__init__.py` creation MUST NOT overwrite existing files (guard with `not init_file.exists()`) to support `--smart-regen`
5. **FR-5**: A unit test MUST verify that `_setup_output_directories()` creates `__init__.py` in all 6 subdirectories
6. **FR-6**: An integration test MUST verify that a full codegen run produces `__init__.py` in all subdirectories
