## 2. Phase 0 — codegen gap found and FIXED (same landing unit)

A3 ("codegen emits one EntryPoint even at zero channels") was **falsified** against the real CLI. A
minimal zero-entry model generates a package with a real module + ExitPoint but **no EntryPoint**
(`pipeline_yaml.jinja2:11` gates it behind `{% if entry_points %}`), and stock TEAx rejects it:

```
$ entry_point_validate(".../zero_channel/pipelines/pipeline.yaml")
REJECTED: ValidationError -> Pipeline must declare exactly one EntryPoint module
```

**Fixed in codegen** (owner directive to combine root-cause edits): `pipeline_yaml.jinja2` now emits
`entry_fusion` unconditionally (empty `inputs:` at zero); TEAx accepts a zero-output EntryPoint
natively. Byte-identity: only `sample_model.yaml` (a zero-entry baseline) changed; all channel-bearing
packages regenerated byte-identical. Full licensed codegen suite 3083 passed + the one expected
baseline update. The end-to-end zero coordinate is now a committed real package (see §4). Details:
`codegen-gap-zero-entry.md`.
