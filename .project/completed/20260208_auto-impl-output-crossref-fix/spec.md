## Problem Statement

### Current State

`_build_auto_impl_context()` in `stencils.py` (line 149) splits compilation results into two categories:

1. **Undeclared intermediates** → emitted as local variable assignments via `execution_steps`
2. **Declared outputs** → inlined directly in the return tuple via `output_expressions`

When declared output B references declared output A (e.g., `f_recirculating = 1.0 / q_eng`), output A's expression is inlined in the return tuple — `q_eng` is never assigned as a local variable. Output B's expression references `q_eng` by name, producing `NameError`.

**Generated (buggy):**
```python
return (
    (inputs.p_electric_gross / inputs.p_auxiliary_total),  # q_eng
    (1.0 / q_eng),           # NameError: q_eng not defined
    (inputs.p_electric_gross * (1.0 - f_recirculating)),  # NameError
)
```

**Expected (correct):**
```python
q_eng = inputs.p_electric_gross / inputs.p_auxiliary_total
f_recirculating = 1.0 / q_eng
p_net = inputs.p_electric_gross * (1.0 - f_recirculating)
return (q_eng, f_recirculating, p_net)
```

### Desired Outcome

Declared outputs that are referenced by later declared outputs MUST be emitted as local variable assignments before the return statement, same as undeclared intermediates. The return tuple MUST reference them by name.

### Edge Cases & Considerations

- **All outputs reference predecessors (full cascade):** Every output except the first references an earlier output. All should be local vars; return tuple references names only. (EngineeringQFactor is this pattern: q_eng → f_recirculating → p_net)
- **Only some outputs reference predecessors (partial cascade):** Output A is standalone, output B references A, output C is standalone. A and C could be inlined; B must reference A by name. Simplest correct approach: emit ALL declared outputs as local assignments when ANY cross-reference exists.
- **Single-output CalcDef:** No cross-references possible. Must remain unaffected (inline in return statement).
- **Undeclared intermediates + declared cross-references:** Both patterns coexist. Undeclared intermediates are already emitted as local vars. Declared cross-references should follow the same pattern. (Not currently seen in test models but architecturally possible.)

---

## Requirements

### Functional Requirements

1. **FR-1**: When a multi-output CalcDef has declared outputs that reference other declared outputs, the referenced outputs MUST be assigned as local variables before the return statement.
2. **FR-2**: The return tuple MUST reference locally-assigned outputs by name, not by re-inlining the expression.
3. **FR-3**: Single-output CalcDefs MUST NOT be affected (continue to inline in return statement).
4. **FR-4**: Undeclared intermediate handling MUST NOT regress (MagnetCryogenicLoad pattern continues to work).
5. **FR-5**: [INFERRED] The detection mechanism SHOULD inspect `CompilationResult.python_expression` strings for references to sibling output names, OR use the expression AST's reference information from `CalcDefCompilationResult.output_results`.
