# 22 -- Output Schema Rules: MultiOutput vs RootModel

## The Decision: Single vs Multi-Output

Every pipeline module produces outputs. The schema depends on output count:

| Output Count | Schema Type | Wrapper | Field Names |
|:---:|---|---|---|
| 1 | `RootModel[float]` (alias `Float`) | No schema file | `"root"` |
| 2+ | Named `MultiOutput` subclass | Schema file generated | Attribute names |

**Decision function**: `should_use_multioutput()` at `generation/schemas.py:103-113`:

```python
def should_use_multioutput(calc_def: CalculationDefinitionData) -> bool:
    return len(calc_def.output_attributes) >= 2
```

## Single-Output Modules

Return `Float` (`RootModel[float]`) from `generation/primitives.py`:

```python
Float = RootModel[float]
```

Module wrapper template (`teax_module.py.jinja2:36`):
```python
class EnergyProductionCalcModule(ModuleBase[EnergyProductionInput, Float]):
    def run(self, ...) -> ModuleResult[Float]:
        result = run_energyproductioncalc(validated)
        return ModuleResult(data=Float(result))
```

No schema file generated. Output field_name in `ModuleOutput` is `"root"`.

## Multi-Output Modules

Generate a named Pydantic class inheriting `MultiOutput`:

```python
# Generated by schemas.py using multioutput_model.py.jinja2
class PVModuleCostOutput(MultiOutput):
    material_cost: float = Field(description="material_cost output")
    fab_cost: float = Field(description="fab_cost output")
    total_cost: float = Field(description="total_cost output")
```

Module wrapper returns this class:
```python
class PVModuleCostCalcModule(ModuleBase[PVModuleCostInput, PVModuleCostOutput]):
    def run(self, ...) -> ModuleResult[PVModuleCostOutput]:
        result = run_pvmodulecostcalc(validated)
        return ModuleResult(data=PVModuleCostOutput(
            material_cost=result[0], fab_cost=result[1], total_cost=result[2],
        ))
```

## The Default Value Constraint

**Template** (`multioutput_model.py.jinja2:12-16`):

```jinja2
{% if field.default %}
    {{ field.name }}: {{ field.type }} = Field(default={{ field.default }}, ...)
{% else %}
    {{ field.name }}: {{ field.type }} = Field(...)
{% endif %}
```

**Source of defaults**: `AttributeInfo.default_value` from extraction. If a
SysML output attribute has a default value, it flows through to `Field(default=...)`.

### Why Defaults on Outputs Can Break TEAx

TEAx's `create_registry()` uses Pydantic introspection to detect output
fields. Its heuristic: **fields without defaults are outputs; fields with
defaults are optional parameters.**

When `Field(default=0.0)` appears on an output field:
1. TEAx treats it as optional, not a required output
2. The field is not registered as a pipeline output channel
3. Downstream modules looking for that channel get `None`
4. Pipeline wiring fails silently

**The rule**: Output fields on `MultiOutput` subclasses MUST NOT have
`default=...` values. If a SysML output attribute has a default, the
generation layer should strip it before rendering the schema.

**Current status**: The template conditionally adds defaults based on
`AttributeInfo.default_value`. Most SysML output attributes don't have
defaults (outputs are computed, not defaulted), so this rarely triggers.
When it does (e.g., aggregation totals initialized to 0), it breaks TEAx.

---

## Aggregation and Computed Attribute Outputs

Both are always single-output: `field_name = "root"`, `python_type = "float"`,
use `RootModel[float]`. No MultiOutput schema generated. No default value risk.

Output channels use PQN format: `get_channel_name(usage_qn, attr_name)` ->
`"{usage_qn}__{attr_name}"`. See doc 15 for full naming conventions.
