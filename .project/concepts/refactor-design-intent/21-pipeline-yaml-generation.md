# 21 -- Pipeline YAML Generation: Channel Formats and Type Rules

## What pipeline.yaml Contains

The pipeline YAML defines execution order, module wiring, entry points, and
exit points. Generated by `generation/pipeline.py:24-63` from `ComputationGraph`
alone -- no raw extraction data needed. This is the "gold standard" generator
(see doc 08).

---

## The Generator Function

```python
def generate_pipeline_yaml(
    graph: ComputationGraph, package_name: str, template_env: Environment,
) -> str:
```

**Steps**:
1. Build `channel_field_map` from all module outputs (lines 47-51)
2. Build entry points context (line 56)
3. Build module contexts with input source formatting (line 57)
4. Build exit points context (line 58)
5. Render `pipeline_yaml.jinja2`

## Input Source Formatting Rules

Every `ModuleInput` has a `source` (`InputSource`) that is either a module
output or an entry point. The formatting differs:

### MODULE_OUTPUT Sources (lines 155-164)

```python
channel = inp.source.producer_channel
producer_field = channel_field_map.get(channel, "")
if producer_field == "root":
    source = f"{channel}.root"    # Single-output: extract .root
else:
    source = channel              # Multi-output: use channel directly
```

**Examples**:
```yaml
# Single-output upstream (RootModel[float]):
p_net_mw: float Design__plant__p_net_kw__p_net_kw.root

# Multi-output upstream (named field):
material_cost: float Design__plant__pv_module__cost_model__material_cost
```

### ENTRY_POINT Sources (lines 166-171)

```python
if inp.source.param_group:
    source = f"{inp.source.param_group}.{inp.source.qualified_name}"
else:
    source = inp.source.qualified_name
```

**Format**: `{param_group}.{qualified_name}` -- ALWAYS includes param group.

**Examples**:
```yaml
# Design attribute:
p_net_mw: float design_params.Design__plant__energy_production__p_net_mw

# Library default:
cost_per_watt: float library_params.Design__plant__pv_module__cost_model__cost_per_watt

# System design (orphan group):
misc_cost: float system_design.Design__plant__misc_cost
```

## The channel_field_map

Pre-built lookup from all module outputs. Maps channel name to field name.

```python
channel_field_map = {
    out.channel_name: out.field_name
    for module in graph.modules
    for out in module.outputs
}
```

**Purpose**: Determines whether to append `.root` when consuming an upstream
module's output. If producer's `field_name == "root"`, consumer must extract
`.root` from the `RootModel[float]` wrapper.

## Type Mapping Rules

Input types are set during module construction in `graph_builder.py`, not
during YAML generation. The YAML just passes through `ModuleInput.python_type`.

| Context | Type | Source |
|---------|------|--------|
| CalcUsage inputs | `"float"` | graph_builder.py:1359-1365 |
| Computed attribute inputs | `"float"` | graph_builder.py:734-738 |
| Aggregation term inputs | `"float"` | graph_builder.py:1015 |
| Aggregation multiplicity | `"int"` | graph_builder.py:1039 |

**Multiplicity is the ONLY `int` type** in the entire pipeline. All other
inputs are `float`. This matters because TEAx expects `float` for
numeric computations -- `int` multiplicity counts must be compatible.

```python
# graph_builder.py:1037-1045
inputs.append(ModuleInput(
    param_name=term.multiplicity_attr,
    python_type="int",    # <-- ONLY int usage
    source=InputSource(...)
))
```

## Output Type Rules

Output types in YAML are determined by `field_name`:

```python
# pipeline.py:189-199
if out.field_name == "root":
    output_type = f"RootModel[{out.python_type}]"   # Single-output
else:
    output_type = out.python_type                     # Multi-output
```

**Examples**:
```yaml
# Single-output module:
outputs:
  root: RootModel[float] Design__plant__energy_production__annual_energy_mwh

# Multi-output module:
outputs:
  material_cost: float Design__plant__pv_module__cost_model__material_cost
  fab_cost: float Design__plant__pv_module__cost_model__fab_cost
```

## Exit Points

All module outputs become exit points (`pipeline.py:202-233`):

```python
for module in modules:
    for out in module.outputs:
        exit_points.append({
            "name": out.channel_name,
            "type": f"RootModel[{out.python_type}]" if out.field_name == "root"
                    else out.python_type,
        })
```

Template renders as:
```yaml
exit_point:
    module_type: ExitPoint
    outputs:
      {channel_name}: {type} {channel_name}.json
```

## Module Source Markers

Comment lines above each module indicate its origin:

```python
# pipeline.py:121-128
"name": (
    f"source: aggregation ({module.module_type})"
    if module.is_aggregation
    else f"source: computed_attribute ({module.module_type})"
    if module.is_computed_attribute
    else module.module_type
),
```

**Examples**:
```yaml
# solarbatterylibrary.EnergyProductionCalcModule           (CalcUsage)
# source: computed_attribute (solarbatterydesign.p_net_kwModule)  (FORMULA)
# source: aggregation (solarbatterylibrary.Capital_CostModule)   (Aggregation)
```

## Entry Point Module and Concrete Example

The first YAML module loads JSON files -- one per `ParameterGroup`:

```yaml
entry_fusion:
    module_type: EntryPoint
    inputs:
      library_params: LibraryParams ../inputs/library_params.json
      design_params: DesignParams ../inputs/design_params.json
```

A regular module entry combines all formatting rules:

```yaml
# solarbatterylibrary.BatteryCostCalcModule
design__plant__battery_cost_calc:
    module_type: solarbatterylibrary.BatteryCostCalcModule
    inputs:
      capacity: float design__plant__size_calc__capacity.root
      unit_cost: float design_params.Design__plant__battery_cost__unit_cost
    outputs:
      root: RootModel[float] design__plant__battery_cost_calc__battery_cost
```
