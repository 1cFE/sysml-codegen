# 20 -- Module Registry Generation: Import Paths and Type Derivation

## What the Registry Does

The generated `__init__.py` registers all pipeline modules with TEAx so the
runtime can discover and instantiate them. It contains:

1. **Import statements** for every module class
2. **`create_registry()`** call with all module classes
3. **`module_type_override`** mapping class names to namespaced types
4. **`CUSTOM_SCHEMA_TYPES`** for entry point and exit point type registration

**Source**: `generation/registry.py:65-156`, template `registry_function.py.jinja2`.

---

## The Problem: Bug 8

Phase 5 validation (fusion-tea e2e) found two sub-problems in the generated
`__init__.py` for hierarchy models:

**8a -- Wrong import paths for aggregation modules**: The registry used
library-based paths (e.g., `solarbatterylibrary.solar_array.capital_cost`)
instead of design-scoped paths (e.g., `solarbatterydesign.solar_battery_plant.solar_array.capital_cost`).
Imports fail at runtime because the files live under the design namespace.

**Root cause**: `registry.py:126` uses `agg.expression.owning_part_qn` (library QN)
instead of `agg.module_eqn` (design-scoped EQN). The CLI module generation
at `cli/__init__.py:417-441` correctly uses `module_eqn`, creating an
inconsistency between where files are generated and where the registry imports from.

**8b -- Class name collisions**: 20 aggregation modules across 4 assemblies
share 5 class names (`Capital_CostModule`, `Raw_Material_CostModule`, etc.).
The `module_type_override` dict uses class name as key, so the last entry
silently overwrites earlier ones.

## Requirements

| ID | Requirement | Traces to | Verified by |
|----|-------------|-----------|-------------|
| REQ-REG-01 | Aggregation module import paths SHALL use design-scoped EQN (`module_eqn`), not library QN (`owning_part_qn`) | Bug 8a | Import paths match filesystem: `from {pkg}.modules.{design_path} import {Class}` |
| REQ-REG-02 | Import paths in registry SHALL match actual filesystem paths generated by CLI | Bug 8a | `import {path}` succeeds for every module in registry |
| REQ-REG-03 | Class names in `module_type_override` dict SHALL be globally unique | Bug 8b | `len(dict.keys()) == len(all_modules)` |
| REQ-REG-04 | When class names collide, registry SHALL use aliased imports (`import X as Assembly_X`) | Bug 8b | No two modules share the same unaliased class name in registry |
| REQ-REG-05 | CalcUsage, computed attribute, and aggregation modules SHALL all derive paths from design-scoped qualified names | Bug 8a | Same `SysMLQualifiedName` derivation for all three module types |
| REQ-REG-06 | `CUSTOM_SCHEMA_TYPES` SHALL include all exit point primitive types used by any module | TEAx integration | Schema type registration covers all output types |
| REQ-REG-07 | Registry generation SHALL detect and report name collisions before rendering | Bug 8b | Warning emitted when two modules produce same class name |

## Module Type Derivation

Every module needs a `module_type` string (namespaced PascalCase) and a
corresponding Python import path. Both derive from a SysML qualified name
via three classes in `resolution/identifier_types.py`:

```python
class SysMLQualifiedName:
    """Parse 'Lib::Part::element' into segments."""
    package_segments: list[str]   # All but last
    element_name: str             # Last segment

class ModuleType:
    @classmethod
    def from_sysml(cls, sqn: SysMLQualifiedName) -> "ModuleType":
        namespace = ".".join(s.lower() for s in sqn.package_segments)
        class_name = f"{sqn.element_name}Module"
        return cls(f"{namespace}.{class_name}" if namespace else class_name)

class PythonModulePath:
    @classmethod
    def from_sysml(cls, sqn: SysMLQualifiedName) -> "PythonModulePath":
        directory = "/".join(s.lower() for s in sqn.package_segments)
        return cls(directory, sqn.element_name.lower())
```

These classes work correctly -- the bug is in what QN they're fed, not how
they transform it.

## Concrete Example: Correct vs Buggy Path

**Aggregation**: `solar_array` assembly's `capital_cost` attribute.

```
CORRECT (design-scoped, using module_eqn):
  Input QN: "SolarBatteryDesign::solar_battery_plant::solar_array::capital_cost"
  → SysMLQualifiedName: segments=["SolarBatteryDesign","solar_battery_plant","solar_array"], elem="capital_cost"
  → PythonModulePath: "solarbatterydesign/solar_battery_plant/solar_array/capital_cost.py"
  → Import: from pkg.modules.solarbatterydesign.solar_battery_plant.solar_array.capital_cost import Capital_CostModule

BUGGY (library-based, using owning_part_qn):
  Input QN: "SolarBatteryLibrary::Solar_Array::capital_cost"
  → SysMLQualifiedName: segments=["SolarBatteryLibrary","Solar_Array"], elem="capital_cost"
  → PythonModulePath: "solarbatterylibrary/solar_array/capital_cost.py"
  → Import: from pkg.modules.solarbatterylibrary.solar_array.capital_cost import Capital_CostModule
  → FAILS: file lives in solarbatterydesign/ not solarbatterylibrary/
```

**The fix**: Change `registry.py:126` from `agg.expression.owning_part_qn` to
`agg.module_eqn.replace("__", "::")`, matching the CLI generation pattern.

## Name Collision Example

5 aggregation attributes (`capital_cost`, `raw_material_cost`, `fabrication_cost`,
`installation_cost`, `idiot_index`) across 4 assemblies produce 20 modules
but only 5 unique class names:

```
solar_array::capital_cost      → Capital_CostModule
battery_system::capital_cost   → Capital_CostModule  (collision!)
site_infra::capital_cost       → Capital_CostModule  (collision!)
plant::capital_cost            → Capital_CostModule  (collision!)
```

**Current `module_type_override` is a dict with class name as key** -- last
entry silently overwrites. Per REQ-REG-04, the fix requires aliased imports:

```python
from pkg.modules...solar_array.capital_cost import Capital_CostModule as SolarArray_Capital_CostModule
from pkg.modules...battery_system.capital_cost import Capital_CostModule as BatterySystem_Capital_CostModule
```

## Template Rendering

**Template**: `registry_function.py.jinja2`

```python
def {{ function_name }}():
    return create_registry(
        [{% for module in all_modules %} {{ module.class_name }}, {% endfor %}],
        module_type_override={
            {% for module in all_modules %}
            {{ module.class_name }}: "{{ module.module_type }}",
            {% endfor %}
        },
    )
```

Per REQ-REG-03, when aliases are used, `module.class_name` must be the
alias (e.g., `SolarArray_Capital_CostModule`), not the original class name.
