SysML Glossary

PartDefinition
A blueprint for a reusable component. Defines attributes, constraints, and sub-parts but is not itself instantiated. Think of it as a class definition.
part def 'PV Module' {
  attribute wattage : ISQ::PowerValue;
  attribute efficiency : Real;
}
PartUsage
An instance of a PartDefinition placed inside a design. Can have multiplicity (how many copies). This is what actually exists in the physical system.
part pv_module : 'PV Module' [20];
// 20 PV modules in the solar array
CalcDefinition
A named calculation with typed inputs and outputs. Defines the math but not the data source. Like a function signature with implementation.
calc def PVModuleCostCalc {
  in wattage : Real;
  in cost_per_watt : Real = 1.07;
  return total_cost : Real = wattage * cost_per_watt;
}
CalcUsage
An instance of a CalcDefinition wired into a Part. The bindings connect the calc's inputs to the part's attributes, making the abstract calculation concrete.
calc cost_model : PVModuleCostCalc {
  in wattage = wattage;
}
Binding (in param = source)
Wires a calculation input to a data source. The source can be a sibling attribute, a parent attribute, or left unbound (falling back to the calc def's default).
in wattage = wattage;
// calc input "wattage" ← part attribute "wattage"
:>> Redefinition
Overrides an inherited attribute with a new value or computation. In the design, :>> pv_module.wattage = 400.0 replaces the blueprint's generic attribute with a concrete design value.
:>> pv_module.wattage = 400.0;
// override: PV Module wattage is 400W in this design
Multiplicity [N]
Specifies how many instances of a part exist. pv_module [20] means 20 PV modules. In aggregation, sum(pv_module.cost) sums across all 20 instances, which decomposes into cost * 20.
part pv_module : 'PV Module' [module_count];
// module_count = 20 in this design
sum() Aggregation
Sums an attribute across all instances of a multiplicity part. The pipeline decomposes sum(part.attr) into part_attr * count, making multiplicity an entry point parameter rather than a runtime loop.
attribute capital_cost =
  sum(pv_module.capital_cost)
  + array_bos.capital_cost;
// → pv_capital * 20 + bos_capital

6.5 Compile Expressions

Compile CalcDef expressions to Python. Each CalcDef's output expressions are parsed into an AST and compiled. The compilation verdict (FULLY_COMPILABLE, PARTIALLY_COMPILABLE, MANUAL_REQUIRED) determines whether the module gets auto-generated implementation or a handwritten stencil.

→
Without compilation, every module needs a handwritten implementation file. Compilation makes the pipeline self-sufficient for straightforward calculations — the generated code is complete, not just wiring.
